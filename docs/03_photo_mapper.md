# PT Photo Mapper

Плагин калибрует положение камеры для каждого фото. Находит
позу, при которой 3D-модель проецируется на фотографию с
минимальной ошибкой, и сохраняет соответствия «вершина ↔
пиксель на фото» в JSON.

## Зачем

Чтобы перенести текстуру с фото на модель, нужно знать точное
положение камеры в момент съёмки. По EXIF известны фокусное
расстояние и размер сенсора, но не положение и поворот.
Vertex Mapper решает эту задачу: пользователь расставляет
6+ пар «3D-вершина ↔ точка на фото», алгоритм вычисляет позу.

Результат — `*.vertices.json`, который используется в
`transfer_blender.py` для проецирования текстур.

**Когда:** для каждого фото, после [Layout Mapper](02_layout_mapper.md).

## Установка

1. `addons/PT_photo_mapper.zip` →
   `Edit → Preferences → Add-ons → Install...`
2. Включить галочку `PT Photo Mapper`.
3. **Перезапустить Blender** (обязательно).
4. Панель: `N` → вкладка **PT Mapper** → **PT Photo**.

## Пошагово

### 1. Загрузить фото

**Photo** — путь к фото. **Camera Start** — начальное
положение камеры (спереди / сзади / справа / слева / сверху).
Выбирайте по ракурсу съёмки.

**Load Photo & Setup Camera**:
- создастся камера `PBA_VM_Camera` с фокусным из EXIF;
- встанет на стартовую позицию в 5 м от центра;
- включится фон с фото (alpha 0.5).

Ожидаемый лог:
```
[PBA VM] Кроп: реальное 3228×2598, нативное 5568×3712
[PBA VM] Фото: 3228×2598, focal=26.5мм, sensor=23.50мм,
старт: справа (-Y). Numpad 0 — вид из камеры.
```

### 2. Выровнять камеру грубо

`Numpad 0` — вид из камеры. Подкрутить `G`, `R` мышью, чтобы
3D-модель примерно совпала с фото. Не нужно идеально —
Solve уточнит.

### 3. Расставить пары

Для каждой характерной точки:
1. `Tab` → Edit Mode → выделить **одну** вершину на модели.
2. **Pick 3D Vertex** — вершина запомнилась.
3. В виде из камеры кликнуть в соответствующую точку на фото.
   Это делается через **Pick 2D on Photo** (модальный
   режим: клик по фото, `ESC` — отмена).
4. Пара добавилась в список.

**Сколько пар:** минимум **6**, оптимально **10–15**. Точки
должны быть разнесены по кадру и не лежать в одной
плоскости (иначе PnP выродится).

**Хорошие точки:** углы кузова, стыки панелей, границы
окон, центры колёс. **Плохие:** точки внутри плоской панели.

### 4. Solve Camera

Кнопка **Solve**. Алгоритм:
- DLT для начального приближения;
- Levenberg-Marquardt для уточнения с фиксированным фокусным;
- многозапуск из разных стартовых позиций (защита от
  локальных минимумов).

Ожидаемый лог:
```
[PBA solve] ПОЛУЧЕНО: rmse=5.200, k1=+0.0000, k2=+0.0000
[PBA per-pair] ошибки:
  pair 0: 3.98 px
  pair 1: 4.16 px
  ...
[PBA VM] Ошибка: средняя 4.89px, макс 8.76px.
```

**Ориентир:** средняя 4–8 px — хорошо. 10–15 px — приемлемо.
Больше 30 px — что-то не так (см. «Частые проблемы»).

### 5. Обработать выбросы

**Diagnose Pairs** — пересчитать ошибки текущего решения.

**Remove Outliers** — удалить пары с ошибкой > 2.5 × медианы.
После удаления автоматически пересчитывается Solve, если
осталось ≥6 пар.

Иногда достаточно удалить одну-две пары, чтобы средняя
ошибка упала вдвое.

### 6. Сохранить

**Save Vertex Positions** — сохраняет рядом с фото два файла:
- `DSC_2505.vertices.json` — для последующих шагов;
- `DSC_2505.vertices.csv` — для отладки/анализа в Excel.

Ожидаемый лог:
```
[PBA VM] Сохранено: .../DSC_2505.vertices.json (пар: 15)
```

## Дополнительные инструменты

### Работа с парами

- **Клик по строке в списке** — выделяет соответствующую
  вершину на модели (Edit Mode) и ставит туда 3D-курсор.
- **X** рядом со строкой — удалить пару.
- **Disable Sel. / Enable Sel.** — отключить/включить пары,
  чьи вершины выделены в Edit Mode. Удобно для исключения
  целой области (например, деформированного кузова).
- **Sort Pairs** — сортировка: сначала по объекту, потом
  сверху вниз-слева направо по фото.

### Snap to Click

Кнопка `SNAP_VERTEX` (магнит) рядом с парой. Сдвигает
3D-вершину так, чтобы её проекция **точно совпала** с
2D-кликом. Глубина при этом сохраняется.

**Зачем:** если модель немного расходится с реальностью в
конкретной точке (изгиб кузова, дефект), Snap выравнивает
её под фото одним кликом.

### Nudge Vertex

Секция в панели для точного сдвига выделенных вершин.
Шаг задаётся в метрах (по умолчанию 0.01 = 1 см).
Кнопки ±X, ±Y, ±Z.

**Зачем:** когда нужно подвинуть вершину ровно на 2 см —
мышью это сложно, кнопкой точно.

## Настройки кратко

| Параметр | Значение | Смысл |
|---|---|---|
| Camera Start | по ракурсу | Стартовая позиция камеры |
| Restore from JSON | включено | Автовосстановление при загрузке фото |
| use_distortion | **выключено** | Коррекция дисторсии (см. ниже) |
| Huber delta | 0 | Устойчивый LM, 0 = отключён |
| Nudge step | 0.01 м | Шаг сдвига вершин |

**Про дисторсию:** в 99% случаев оставляйте **выключенной**.
Современные камеры уже применяют коррекцию в JPEG, и оптимизация
k1/k2 начинает компенсировать шум разметки, а не реальную
оптику. Включать только для явно дисторсированных фото
(широкоугольная оптика, ручная разметка без коррекции).

## Частые проблемы

**Большая ошибка на фото (300+ px) при чтении JSON.**

Причина: модель изменилась (топология или позиции вершин),
`x_world` в JSON устарел. `_sync_x3d_from_mesh` перед solve
обновляет координаты — но если модель переделана сильно,
надо переразметить.

Смотрите в лог строки `ПОДОЗРИТЕЛЬНО: сдвиг X.XXX м`. Если
их много — модель серьёзно изменилась.

**Дубликаты вершин в логе.**

`[PBA VM] 3D: Right_side v128 = (...)` дважды. Это UI
печатает одно и то же. На результат не влияет, дубликаты
пар не добавляются (`_commit_pair` отсекает по UUID).

**Solve уходит в мусор, ошибка 1000+ px.**

Причины:
1. **Мало пар** (<6). Добавьте ещё.
2. **Все точки в одной плоскости** (вид строго сбоку).
   Добавьте 2–3 точки на другой плоскости (например,
   переднюю грань).
3. **Ошибка в парах** — попробуйте `Diagnose Pairs`,
   удалите выбросы.
4. **Неверный Camera Start** — если модель на старте совсем
   не в кадре, LM не сойдётся. Перезагрузите фото с другим
   стартом.

**Камера встала, но всё равно смещение по краям.**

Остаточная дисторсия объектива. Либо прогоните фото через
darktable с коррекцией по профилю объектива, либо
смиритесь — 5–10 px на краях не критично.

**`нет UUID у вершины` при Pick 3D.**

Не назначены UUID (шаг 1 в UV Exporter). Прогнать
`Assign Vertex UUIDs` там и вернуться.

**`Восстановлено: N пар, потеряно по UUID M`.**

При загрузке JSON некоторые вершины не нашлись по UUID.
Причина: модель переделана сильнее, чем позволяет
UUID-механизм. Пара будет пропущена; её нужно разметить
заново.

## Порядок работы для нескольких фото

1. Для каждого фото: загрузить → выровнять → 10+ пар →
   Solve → сохранить JSON.
2. После всех фото — переходить к Layout Mapper.

Не нужно перезапускать Blender между фото. Просто
`Clear All Pairs` в панели и загрузить следующее.
